# EXECUTION PROTOCOL — Cách Codex phải làm việc

1. Đọc toàn bộ prompt này.
2. Xác nhận đang ở `coach1`.
3. Thực hiện đúng Phase 00 trước.
4. Không triển khai hai phase cùng lúc.
5. Đầu mỗi phase:
   - đọc code liên quan.
   - ghi kế hoạch file sẽ sửa.
   - ghi risk.
6. Cuối mỗi phase:
   - chạy test tối thiểu liên quan.
   - chạy backend build nếu backend đổi.
   - chạy frontend TypeScript/build nếu frontend đổi.
   - cập nhật progress document.
   - chạy `git diff --check`.
7. Không sang phase tiếp theo nếu:
   - build fail.
   - test critical fail.
   - migration mismatch.
   - có thay đổi ngoài scope chưa giải thích.
8. Nếu blocker pre-existing thuộc Marketplace/Seller:
   - ghi rõ.
   - không sửa ngoài scope.
   - dùng Coach disposable acceptance DB nếu phù hợp.
9. Mỗi phase ưu tiên một commit độc lập.
10. Không push.
11. Không squash lịch sử của người dùng.
12. Không dùng `git reset --hard`.
13. Không xóa untracked file của người dùng.
14. Không tuyên bố hoàn thành dựa trên việc “code có route”.
15. Chỉ tuyên bố PASS khi có test evidence.
